Paso 0

Instalar

El instalador descarga un binario público verificado desde GitHub Releases. No requiere una cuenta ni un token de GitHub.

Binario (Linux / macOS · x64 / arm64)

curl -fsSL https://raw.githubusercontent.com/unbroker-app/ubctl/main/scripts/install.sh | bash

npm (GitHub Packages)

# una sola vez: apunta el scope a GitHub Packages y autentícate
echo "@unbroker-app:registry=https://npm.pkg.github.com" >> ~/.npmrc
echo "//npm.pkg.github.com/:_authToken=TU_GITHUB_TOKEN" >> ~/.npmrc

npm install -g @unbroker-app/ubctl   # instala el comando `ubctl`

Paso 1

Autenticarse

ubctl login valida tu token de API contra el servidor y lo guarda localmente en ~/.config/ubctl/config.json (con permisos 0600). El secreto se envía como X-API-Key en cada petición. 

ubctl login                 # pide el token de forma interactiva (oculto)
ubctl login --token ub_live_… # o pásalo directo
echo "$TOKEN" | ubctl login --stdin  # o por stdin (CI)

ubctl whoami                # confirma la cuenta y la organización activa

Al autenticarte correctamente, el CLI muestra una interfaz compacta con la identidad del token o usuario, la organización activa, el endpoint de API, la ruta de configuración y los siguientes comandos recomendados. Para automatizaciones, usa ubctl --json login --stdin y recibirás solamente JSON estructurado. 

╭──────────────────────────────────────────╮
│ UNBROKER CLOUD                           │
│ ✓ Authenticated                          │
├──────────────────────────────────────────┤
│ Identity  API token "mi-cli"             │
│ Org       mi-organizacion                │
│ API       https://api.unbroker.cloud     │
├──────────────────────────────────────────┤
│ Next: ubctl apps projects ls             │
│ Help: ubctl --help                       │
╰──────────────────────────────────────────╯
De dónde sale el token: créalo en el panel de Unbroker o con ubctl tokens create --name mi-cli. El secreto ub_live_… se muestra una sola vez — guárdalo en el momento. En el servidor se almacena solo su hash, nunca en texto plano.

Paso 2

El flujo completo de una app

De cero a una URL en vivo: un proyecto contiene servicios, cada servicio se despliega desde un repo de GitHub y produce deployments inmutables.

1

Crear un proyecto

Contenedor de servicios. El slug se genera a partir del nombre. 

ubctl apps projects create --name "Mi App"
ubctl apps projects ls
2

Crear un servicio

Apunta a un repo público de GitHub y elige el framework. Opcional: rama, comandos de build/start, puerto. 

ubctl apps services create <projectId> \
  --name web \
  --repo https://github.com/mi-org/mi-repo \
  --framework next \
  --branch main
3

Desplegar y seguir el pipeline

--wait sigue el deployment hasta que termina, imprimiendo cada transición de estado. 

ubctl apps deploy <serviceId> --wait
4

Inspeccionar

Historial de deployments, logs de runtime y métricas en vivo.

ubctl apps deployments <serviceId>
ubctl apps deployment <deploymentId> --log
ubctl apps services logs <serviceId>
ubctl apps services metrics <serviceId>

Bajo el capó

El ciclo de vida de un deployment

Cada deploy avanza por una máquina de estados. Con --wait el CLI hace polling y te muestra el avance; si falla, imprime el final del build log y sale con código ≠ 0 (útil como gate en CI).

queued → building → deploying → live ✓ / failed ✕

Un nuevo deploy en vivo marca el anterior como superseded. Volver a una versión previa es instantáneo y no reconstruye: 

ubctl apps rollback <serviceId> <deploymentId>

Paso 3

Variables de entorno & dominios

Variables (valores enmascarados)

ubctl apps env set <svc> DATABASE_URL "postgres://…"
ubctl apps env ls <svc>
ubctl apps env rm <svc> DATABASE_URL

Cambiar variables marca el servicio como “needs redeploy” — no redespliega solo.

Dominios propios

ubctl apps domains add <svc> app.ejemplo.com
ubctl apps domains ls <svc>
ubctl apps domains rm <svc> app.ejemplo.com

Cada servicio ya trae una URL <slug>.apps.cloud.unbroker.app.

Infraestructura

Recursos cloud

Además de las apps (PaaS), ubctl maneja la capa de recursos implementada por el control plane: máquinas y bases de datos administradas.

Comando Qué hace
ubctl droplets ls · get · reboot · power-off · power-on · rm
ubctl db ls · get · connection (credenciales) · rm

Referencia

Flags globales & configuración

Flag / variable Descripción
--json Salida JSON cruda en cualquier comando de lectura (para scripting).
--org <id> Actúa contra una organización concreta (X-Org-Id).
--api-url <url> Sobrescribe la URL base de la API.
UBCTL_TOKEN Token sin guardarlo en disco (ideal para CI).
UBCTL_API_URL URL base por entorno.
Precedencia de configuración: flag → variable de entorno (UBCTL_*) → archivo ~/.config/ubctl/config.json → default (https://api.unbroker.cloud).
