Step 0

Install

The installer downloads a verified public binary from GitHub Releases. It does not require a GitHub account or token.

Binary (Linux / macOS · x64 / arm64)

curl -fsSL https://raw.githubusercontent.com/unbroker-app/ubctl/main/scripts/install.sh | bash

npm (GitHub Packages)

# once: point the scope at GitHub Packages and authenticate
echo "@unbroker-app:registry=https://npm.pkg.github.com" >> ~/.npmrc
echo "//npm.pkg.github.com/:_authToken=YOUR_GITHUB_TOKEN" >> ~/.npmrc

npm install -g @unbroker-app/ubctl   # installs the `ubctl` command

Step 1

Authenticate

ubctl login validates your API token and stores it in ~/.config/ubctl/config.json with 0600 permissions. Each request sends the secret as X-API-Key. 

ubctl login                 # interactive hidden prompt
ubctl login --token ub_live_… # pass it directly
echo "$TOKEN" | ubctl login --stdin  # stdin for CI

ubctl whoami                # confirm identity and active organization

After a successful login, the CLI displays a compact interface with the token or user identity, active organization, API endpoint, config path, and suggested next commands. Automation can use ubctl --json login --stdin for structured JSON output only. 

╭──────────────────────────────────────────╮
│ UNBROKER CLOUD                           │
│ ✓ Authenticated                          │
├──────────────────────────────────────────┤
│ Identity  API token "my-cli"             │
│ Org       my-organization                │
│ API       https://api.unbroker.cloud     │
├──────────────────────────────────────────┤
│ Next: ubctl apps projects ls             │
│ Help: ubctl --help                       │
╰──────────────────────────────────────────╯
Where the token comes from: create it in the Unbroker dashboard or with ubctl tokens create --name my-cli. The ub_live_… secret is shown once; save it immediately. The server stores only its hash, never the plaintext token.

Step 2

Complete app workflow

From zero to a live URL: a project contains services. Each service deploys from a repository and produces immutable deployments.

1

Create a project

A container for services. Its slug is generated from the name. 

ubctl apps projects create --name "My App"
ubctl apps projects ls
2

Create a service

Point it at a supported repository and choose a framework. Optionally set the branch, build/start commands, and port. 

ubctl apps services create <projectId> \
  --name web \
  --repo https://github.com/my-org/my-repo \
  --framework next \
  --branch main
3

Deploy and follow the pipeline

--wait follows the deployment until completion and prints every status transition. 

ubctl apps deploy <serviceId> --wait
4

Inspect

Deployment history, runtime logs, and live metrics.

ubctl apps deployments <serviceId>
ubctl apps deployment <deploymentId> --log
ubctl apps services logs <serviceId>
ubctl apps services metrics <serviceId>

Under the hood

Deployment lifecycle

Every deploy moves through a state machine. With --wait, the CLI polls and displays its progress. On failure it prints the end of the build log and exits non-zero, which is useful as a CI gate.

queued → building → deploying → live ✓ / failed ✕

A new live deploy marks the previous one as superseded. Rolling back is immediate and does not rebuild: 

ubctl apps rollback <serviceId> <deploymentId>

Step 3

Environment variables & domains

Variables (masked values)

ubctl apps env set <svc> DATABASE_URL "postgres://…"
ubctl apps env ls <svc>
ubctl apps env rm <svc> DATABASE_URL

Changing variables marks the service as “needs redeploy”; it does not redeploy automatically.

Custom domains

ubctl apps domains add <svc> app.example.com
ubctl apps domains ls <svc>
ubctl apps domains rm <svc> app.example.com

Every service includes a URL at <slug>.apps.cloud.unbroker.app.

Account

Tokens, usage, and organizations

API tokens

ubctl tokens create --name ci --scope read/write
ubctl tokens ls
ubctl tokens rm <id>

Usage & organizations

ubctl account usage
ubctl account invoices
ubctl account activity
ubctl orgs

Infrastructure

Cloud resources

In addition to apps (PaaS), ubctl manages the control-plane-backed resource layer: virtual machines and managed databases.

Command Operations
ubctl droplets ls · get · reboot · power-off · power-on · rm
ubctl db ls · get · connection (credentials) · rm

Reference

Global flags & configuration

Flag / variable Description
--json Raw JSON output for supported commands and scripting.
--org <id> Target a specific organization (X-Org-Id).
--api-url <url> Override the API base URL.
UBCTL_TOKEN Use a token without saving it to disk (ideal for CI).
UBCTL_API_URL Set the API base URL from the environment.
Configuration precedence: flag → environment variable (UBCTL_*) → config file ~/.config/ubctl/config.json → default (https://api.unbroker.cloud).
